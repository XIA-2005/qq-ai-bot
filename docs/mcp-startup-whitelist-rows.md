# v0.6.0：逐行白名单与每次启动自动回复

## 本次范围

- 停止此前聊天记录与人设任务，不读取 QQ 聊天记录，不改变现有人设。
- 私聊好友白名单、群白名单改为可添加和删除的单号码行。
- 每次完整启动应用，QQ 在线并满足必要配置后自动开启回复。

## 实现

### 白名单

- `ui/whitelist-rows.js`：独立行编辑组件，按字符串处理号码，避免长账号被数值转换损坏。
- 一行一个账号或群号；增加、删除、Enter 添加、批量粘贴自动拆行。
- 每类最多 200 行；空行忽略、重复号码去重；非法号码或同一行混填会阻止保存。
- 删除最后一行后保留一个空白输入行。
- `ui/whitelist-rows.css`：窄窗口单列、正常窗口双列；列表区域独立滚动。
- `ui/app.js`、`ui/index.html` 接入组件；配置仍使用原来的 `friends`、`groups` 字符串数组，兼容原有数据。
- 忽略名单、主动接话专用列表及原有范围校验保持不变。

### 启动自动回复

- `src/config.ts` 在配置校验/旧配置迁移时统一 `autoReplyOnLogin=true`，但不捏造 `autoReplyConsent`，不扩大回复范围。
- UI 不再提供一个与“每次打开自动开启”相冲突的持久关闭开关；保留手动暂停。
- 已记住账号时仍使用原有 QQ 登录恢复流程。没有记住账号、设备验证或恢复失败时，需要先完成登录，不能伪装已连接。
- 登录事件发生后，密钥、白名单、首次确认与请求状态齐全才启动 Engine。
- 手动暂停只暂停当前运行；断线重连不会取消暂停。桌面「保存配置」成功后会解除先前的手动暂停，保持 QQ 登录不变；仅在 QQ、密钥、有效白名单及本版本知情确认齐备时自动开启，否则等待并显示原因。清空记忆、应用人设仍会暂停；完全退出后再打开，新的 AutoReply 实例重新待命。
- `src/auto-reply.ts` 提供等待原因，`src/main.ts` 将其推送给 UI。未配置好、未登录时显示“待自动开启”，不显示虚假的运行中。
- `--pause-replies` 保留为显式诊断暂停参数。
- 启动时不会为了迁移选项重写用户凭据文件；正常保存配置时持久化当前设置。

### 实际打包发现的兼容修复

打包验收时发现：Windows 上运行路径盘符 `d:` 与 Chromium 页面 URL 盘符 `D:` 的差别，导致原有严格 URL 字符串比较把本应用页面误判为“无效请求来源”。

- 新增 `src/ipc-origin.ts`，Windows 下按大小写不敏感方式比对预期文件 URL。
- 保留发送窗口和主框架身份校验。
- 仍拒绝其他文件、远程协议、远程主机、查询参数和片段。
- 此修复后真实 EXE 的 IPC 配置读写通过验收。

- `get_diagnostics`：`src` 范围无错误或警告。

  - 非法混填不改变已保存值，多号码粘贴按行拆分。
  - 删除末行仍可编辑；900px 与 1180px 布局无横向溢出。
  - UI 的添加按钮在 200 行时禁用。
  - 暂停退出再启动后，保存的数据仍存在，状态恢复为“待自动开启”，缺少必要条件时不发送消息。

## 交付与使用

- 版本：0.6.0。
- 主程序：`release-v0.6.0/win-unpacked/QQ AI Bot.exe`。
- 根目录 `启动机器人.exe` 按版本挑选最新目录；`启动机器人.cmd` 已同步指向 v0.6.0。
- 本次为完整目录包，不是新建 NSIS 安装包。必须保留完整 `win-unpacked` 目录及内置运行时。
- 先正常退出旧版，再启动新版。未强制终止用户正在运行的旧版，也未打开用户真实配置下的新版。
- 原配置、API Key、记住账号、人设和主动接话设置继续使用。旧版发布目录保留。
