# 让机器人发送 QQ 表情

承接 `docs/mcp-emoticon-recognition.md`。该文解决了「看懂」对方的表情，本文补上「会发」。

## 1. 为什么只发内置表情 face，不发商城表情 mface

两者的发送成本完全不同：

| 类型 | 发送所需字段 | 可行性 |
|---|---|---|
| `face` | 仅 `id`（数字编号） | 可直接构造 |
| `mface` | `emoji_id`（32 位十六进制）、`emoji_package_id`、`key` | 需要真实表情库，缺一不可 |

NapCat 对 mface 的校验是硬性的：`emojiId must be exactly 32 hexadecimal characters`。
本机没有商城表情素材库，也无法凭空生成合法 id，因此**只实现 face 发送**。
这已覆盖日常聊天的绝大多数表情需求。

## 2. 实现

### 2.1 反向映射 `faceIdForName()`（`src/config.ts`）

由既有的 `FACE_NAMES`（id → 名称）反向构建 `FACE_IDS`（名称 → id），重名时保留首个 id。

模型未必写出与表情表完全一致的名称，因此额外提供 `FACE_ALIASES` 别名表，
把常见说法映射到真实表情名：

- `开心`/`高兴`/`滑稽` → `斜眼笑`
- `谢谢`/`感谢` → `抱拳`
- `点赞` → `赞`，`好的`/`ok` → `OK`
- `狗头` → `doge`，`无语` → `无奈`，`震惊` → `惊恐`

名称同样会剥掉方括号，使入站产生的 `[菜狗]` 能反查回 id `317`。

### 2.2 出站解析 `buildMessageSegments()`（`src/onebot.ts`）

把一行回复文本拆成 OneBot 消息段数组，将 `[表情: 名称]` 替换为真实 `face` 段：

- 正则 `/\[表情[:：]\s*([^\]]{1,20})\]/g`，**半角与全角冒号都支持**（模型常写全角）。
- 名称长度上限 20，避免异常输入造成灾难性回溯。
- **未知名称保持字面文本**，绝不静默丢弃——宁可让用户看到 `[表情: xxx]`，也不能让内容消失。
- 标记前后的文本按原顺序保留，支持一条消息内多个表情。
- 无任何有效表情时退回单个 text 段，行为与改动前完全一致。

`send()` 中 `message.push({type:'text',...})` 改为 `message.push(...buildMessageSegments(part))`，
与 @ 标签、分条发送逻辑天然叠加，无需额外协调。

### 2.3 提示词告知

三条链路都说明了机器人可以发表情，且措辞按场景区分风险：

| 文件 | 措辞要点 |
|---|---|
| `src/config.ts`（私聊/@ 回复） | 可用 `[表情: 名称]` 表达情绪，举例微笑/笑哭/赞/doge，每条最多一个 |
| `src/group-session.ts`（群持续参与） | 群里要克制，一条最多一个，多数时候不用 |
| `src/proactive.ts`（主动接话） | 同上 |

群聊限制更严是刻意的：主动接话本就容易被视为打扰，再配表情会放大刷屏感。

## 3. 验证

`npx tsc --noEmit` 无错误，`get_diagnostics` 0 条，`npm test` **170 pass / 0 fail**
（新增 2 个用例、17 条断言）。

| 输入文本 | 生成的消息段 |
|---|---|
| `[表情: 微笑]` | `face id=14` ✅ |
| `[表情: doge]` | `face id=179` ✅ |
| `[表情: 开心]`（别名） | `face id=178` ✅ |
| `好的 [表情: 微笑]` | `text` + `face` ✅ |
| `真的吗[表情：疑问]我不信`（全角） | `text` + `face` + `text` ✅ |
| `[表情: 赞][表情: 爱心]` | 两个 face 段 ✅ |
| `[表情: 某个不存在的]` | 原样 text，不丢失 ✅ |
| `普通文本` | 单个 text，行为不变 ✅ |

往返一致性：入站产生的 `斜眼笑` 能反查回 `178`，`[菜狗]` 能反查回 `317`。

端到端（群定向回复 + 分条）：

```
"收到啦 [表情: 微笑]\n这个我知道"
  第 1 条: [at:654321, text:" ", text:"收到啦 ", face:14]
  第 2 条: [text:"这个我知道"]
```

@ 标签仍只出现在第一条，表情段正确嵌入。

## 4. 说明与后续

- **只能发内置 QQ 表情，不能发商城表情包**，原因见第 1 节。若确有需求，
  需先在本机建立商城表情素材库（含合法 `emoji_id` 与 `key`），再扩展 `buildMessageSegments`。
- 模型是否发表情、发得是否得体，属于概率行为。别名表覆盖不到的写法会退化为字面文本，
  不影响消息送达；发现高频误写时在 `FACE_ALIASES` 中补充即可。
- 表情不计入 `splitReplyMessages` 的分句逻辑：标记本身是文本的一部分，
  分条完成后才逐行解析成消息段，两者互不干扰。
