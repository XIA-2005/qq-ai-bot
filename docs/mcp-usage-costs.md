# v0.8.2：聊天累计使用金额（估算）

日期：2026-09-21

## 用户确认的范围

用户选择同时显示软件总金额和每个好友/群的金额，并接受按 API 返回 Token 与模型单价估算，跨重启累计。不是查询整个 DeepSeek 账户的历史账单，也不采用余额差额分摊聊天费用。

实现位置：运行概览总额、用量统计页面、逐行白名单的聊天/试聊金额。非聊天用途单独归类，保留已有 API 余额与状态修复。

## 定价依据与限制

官方中文文档：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/
官方英文文档：https://api-docs.deepseek.com/quick_start/pricing/

本次核对的 deepseek-flash 人民币参考价（元/百万 Token）：

| 类型 | 高峰 | 空闲 |
| --- | ---: | ---: |
| 输入缓存命中 | 0.04 | 0.02 |
| 输入缓存未命中 | 2 | 1 |
| 输出 | 8 | 4 |

官方存在高峰/空闲和节假日规则。软件默认采用固定高峰参考价，并提供空闲预设和手动单价；**不自动判断高峰、空闲、节假日或账户优惠**，所以估算可能高于实际扣款。界面明确为人民币估算、非实际账单，不跨币种换算，不保证与余额差额一致。价格只作为本次核对日期的参考。

金额计算使用整数定点：单价转换为百万分之一元，再乘对应 Token；累计金额以 10^-12 元为单位保存，显示 8 位小数。非零但小于显示精度的金额显示小于阈值，不显示成零。

请求开始时捕获保存单价。修改单价需确认，只影响之后开始的请求；历史金额不重算，也不改变提供方的实际价格。

## 记录与归属

- `src/model.ts` 提取输入、输出、总 Token 及缓存命中/未命中；只接受非负安全整数与输入+输出=总数。只有一个有效缓存字段时可由总输入推导另一字段；矛盾的缓存字段不当作可靠拆分。
- 完整输入/输出存在、缓存拆分缺失时，按输入全部未命中估算并单列“缓存拆分缺失”次数；不把缺失信息伪装成实际缓存命中数。
- API 未返回完整用量或响应无效，列为用量不完整；显示金额是已知部分，不把请求当免费，不由字数猜 Token。
- 真实聊天以 `p:<好友号>` / `g:<群号>` 归属；群内各作者合并到群，私聊与同号群仍严格区分。
- 主动接话判断即使选择沉默仍产生模型请求，计入该群。API 已返回用量但 QQ 发送失败、输出被截短、请求取消或回复被丢弃，不撤销已发生的模型用量。
- 独立试聊记录试聊目标，不混入真实聊天；手动验证与原有提炼调用分别列出。没有恢复已取消的聊天记录获取任务。
- 余额查询不属于生成调用，不计入模型用量。
- 软件总计包含本程序使用过的所有 Key。换 Key、删除 Key、清记忆、修改人设、删除白名单都不清零。

## 持久化与中断保护

新增 `src/usage-ledger.ts`，存储到当前 userData 的 `usage-ledger.json`。

- 请求开始前先记一条“用量不完整”，获取完整用量后再补金额；异常退出后未完成的请求仍保留为不完整，不会假装不存在或零消费。
- 每个请求票据仅能结算一次，observer、返回值及 finally 不会重复累计。
- 采用临时文件加 rename 原子替换，记录统计及单价。写盘失败不阻断聊天，界面警告重启可能丢失未保存部分。
- 损坏或不可读的统计文件不被覆盖；累计统计停用并明确显示不可用，不显示虚构的零总额。
- 只保存对象号码、分类汇总 Token、金额和单价，不保存 API Key 或聊天正文。
- 已移出名单的历史统计仍保留；超过 4000 个统计桶的新对象合并到相应用途的“其他历史对象”，总额不丢失。4000 桶按用途与目标组合计数，而非 4000 个当前联系人。
- 从本版第一次模型请求开始累计；无法补算旧版或其他软件的历史消费。

## 界面与接线

- Engine 传递当前 job 元数据，用于私聊/群归属；PreviewSession 捕获请求开始时的目标，切换目标不能把旧请求费用算给新目标。
- 主进程统一通过 completeWithUsage 和用量 observer 记录。完整用量在检查输出文本前提供，避免“模型扣费但无可用文本”漏记。
- `ui/usage-ui.js`：总额、分类、历史对象表格、完整性标识、单价表单。
- `ui/whitelist-rows.js`：每行新增金额提示，不重建或覆盖正在编辑的号码与备注。
- 新增受限 `save-usage-pricing` IPC，不开放任意写统计接口；旧来源检查及 renderer 隔离保持。
- 更新统计不查询账户余额、不发起额外模型请求、不重置自动回复策略。侧栏支持小窗口滚动。

### 重点测试

1. 缓存计价精度、缓存缺失标记、非法用量、价格边界、极小金额显示。
2. 真实聊天/试聊/验证/提炼分类及总额一致，不同好友与同号群独立。
3. 重复结算不双算；价格修改不改变历史和在途请求的捕获价格。
4. 中断请求跨重启仍标记不完整；文件损坏保留原数据；写盘失败不影响模型返回。
5. 主动接话沉默仍记录群费用；取消试聊且收到完整用量时仍归属原目标，不应用迟到回复。
6. 真实 EXE 的统计页面、白名单行、总金额及单价确认。
7. 真实 Engine 使用模拟私聊、群事件与替换后的 QQ 发送桩，验证金额归属；不登录或发送真实 QQ 消息。
8. 真实 EXE 重启后金额、用途分类、目标归属、单价保留；删除 Key 不删统计。

验收全部使用临时 user-data-dir、假 Key、进程内 fetch/模型桩。新增的 Engine 场景在注入事件前替换 QQ 发送函数，完成后暂停并恢复；没有真实外部发送或费用。所有桩仅存在于临时测试进程，未写入交付软件。
