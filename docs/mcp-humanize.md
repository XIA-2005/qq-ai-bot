# 让机器人有「活人感」

提交 `bb04d8b`。目标：让人在群里看不出对面是程序。本轮只做用户选定的五项。

## 1. 打字速度优化

改之前：不管回什么，气泡之间固定停 300ms。两条长句之间也是 300ms，一眼假。

改之后（`src/humanize.ts`）：

| 环节 | 规则 | 区间 |
| --- | --- | --- |
| 思考 | `700 + 38 × 收到消息字数`，抖动 ±30% | 600 – 4200ms |
| 打字 | 按 260 字/分，抖动 ±25% | 450 – 6000ms |

思考只在第一条气泡前发生（读完消息才开始打字），之后每条气泡各自按长度计时。抖动保证同一句话两次发送耗时不同。

实测：

```
收到「在吗」         回「嗯」                  思考 743ms  打字 450ms   共 1.2s
收到「这个方案你觉得行吗」 回「感觉有点离谱，主要是时间根本不够用」  思考 1179ms 打字 3658ms  共 4.8s
同一句「感觉有点离谱」重复五次：1076 / 1382 / 1653 / 1730 / 1244 ms
```

## 2. 「对方正在输入…」

私聊发送前调 `set_input_status`，发送完（或中途抛异常）在 `finally` 里清除，不会把输入状态卡住。

群聊没做——QQ 协议里群聊本身不存在这个状态，不是遗漏。

## 3 & 4. 贴表情回应 / 对没营养的附和沉默

这两件事是同一个判断的两个出口。当机器人**主动发言**或**接龙**时，如果生成的内容只是「哈哈哈」「确实」「666」这类纯附和：有原消息 id 就贴个表情，没有就干脆不发。

```
"哈哈哈"          -> 贴表情 182 笑哭
"666"            -> 贴表情 76  赞
"他说明天十点面试"    -> 正常发送
"确实是这样，但时间来不及了" -> 正常发送
```

判定规则：去掉标点/emoji/`[表情: x]` 后比对词表；纯重复字符（`啊啊啊`）算附和；超过 12 字或含换行一律不算，宁可多发也不吞掉有内容的话。

**关键边界：只作用于机器人自己开口的场合。**别人直接问它、@ 它，哪怕答案就是「嗯」也照发不误——被问到却装死，比话多更像故障。

## 5. 戳一戳

`OneBot.poke()`，群聊走 `group_poke`、私聊走 `friend_poke`。

`react()` 和 `poke()` 都是 best-effort：内部吞掉异常并返回 `false`。贴表情失败绝不能连累正文发送。

## 工程细节

- 三个接口在你机器上实测通过后才写的代码，不是照文档猜的：`set_input_status`、`set_msg_emoji_like`（含 `set:false` 撤销）、`group_poke`。
- `OneBot.humanize` **默认 false**，由 `main.ts` 打开。现有测试会断言 `bot.call` 的精确调用序列，默认开启会让四个测试文件集体失败。
- `bot.pace` 可覆盖，测试里置 0 秒跑完。
- 新增 `tests/humanize.test.cjs`。全量 **187/187 通过**，`tsc --noEmit` 干净。
