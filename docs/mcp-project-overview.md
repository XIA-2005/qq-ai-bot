## 一、项目定位与全景概览

QQ AI Bot 是一款基于 Electron + TypeScript 架构打造的 Windows 绿色桌面端个人 QQ 智能助手。项目通过原生无头整合 NapCatQQ（OneBot v11 协议），无缝串联 DeepSeek 开放平台（文字推理模型与多模态视觉模型），致力于在零门槛、免繁琐配置、免外挂注入的前提下，为用户提供高度智能化、可控、安全且具有“真人感”的个人 QQ 好友与群聊自动化助理。

### 1. 核心技术栈
- **桌面应用外壳**：Electron 40 + Node.js 22+（集成原生系统托盘、Windows DPAPI 安全加密、无边框现代 UI）。
- **QQ 协议核心**：内置免安装的 NapCatQQ 运行时（OneBot v11 协议标准），通过本地环回 WebSocket（`ws://127.0.0.1:3001`）实现双向异步通信；内置 `qrcode` 模块实现本地动态扫码授权。
- **大模型底座**：DeepSeek 开放平台 API（默认 `deepseek-flash` 及视觉多模态能力），结合 Cache-aware Token 解析实现高精度毫厘级费用审计。
- **语言与规范**：TypeScript 5.9（严格类型检查、模块化设计、全套原生 Node.js 测试套件）。
- **工程与打包**：`electron-builder` 绿色便携打包（`win-unpacked`）与 NSIS 安装包。

### 2. 宿主机工程布局
宿主机存在两个主要工作目录：
- **源代码仓库**：`/d/QQ-AI-Bot`（主开发仓库，包含完整的 TypeScript 源码、测试用例、UI 资源与设计文档）。
- **打包输出/运行目录**：`/d/QQ AI Bot EXE`（构建好的 Electron 独立免安装运行目录，内含完整 `napcat-runtime` 与 `app.asar`）。

## 三、核心模块与设计机制深度解析

### 1. 生命周期与登录治理 (`src/login.ts`, `src/login-memory.ts`, `src/main.ts`)
- **守护式子进程管理**：软件启动时动态分配合法的本地端口与随机安全 Token，自动配置并拉起内置 NapCatQQ 运行时，杜绝端口冲突与静态凭证泄漏。
- **免密码扫码授权**：通过 NapCat 内部 WebAPI 拉取二维码凭据并在本地使用 `qrcode` 渲染呈现；全程不接触用户 QQ 账号密码，安全通过官方扫码与二次设备验证。
- **账号记忆与快速重连**：`LoginMemory` 持久化记录最近一次登录的账号元数据（无明文凭据），程序重启后可自动尝试快速拉起对应会话。

### 2. 消息流转与协议解析 (`src/onebot.ts`, `src/config.ts`)
- **OneBot v11 适配**：实时监听 `ws://127.0.0.1:3001` 的事件流，解析 `message`, `notice`, `request`。
- **消息段与 CQ 码提纯**：将 incoming 消息中的 CQ 码转化为标准化结构体，抽离出纯文本、`[表情: 名称]` 情绪标签、图片对象与 @ 实体。
- **出站消息拆分与组装**：
  - `splitReplyMessages`：针对模型输出的换行分段，拆分为多条短消息逐条发送，模拟真人连发。
  - `forceSentenceSplit`：当模型输出过长单句未换行时，依据中文标点进行强制保全式拆行。
  - 特殊符号保护：保留代码块完整性，并在遇到感叹/无奈语句时保留合理停顿。

### 3. 会话调度与限流车道 (`src/scheduler.ts`)
- **车道化并发隔离（Lane Architecture）**：每个私聊用户（`p:<qq>`）与每个群组（`g:<group>`）分配独立的处理车道，避免单个长耗时请求阻塞全系统。
- **静默合并窗口（Debounce Window）**：对方连续发消息时，提供 1.5 秒的静默等待窗口，最多合并 5 秒内的多条连续短句，整合成单轮 Prompt 提交模型，彻底杜绝单字或单句频繁触发 API。
- **安全阈值与排队防爆**：
  - 全局限制最多 3 个独立会话并行。
  - 每分钟全局共享 10 次请求额度。
  - 最大队列深度 20 个任务，超期 60 秒自动抛弃，防止堆积雪崩。

### 4. 拟人化互动与群聊高级模式 (v0.9.0 核心)
- **群聊「@ 一次后持续参与」房间模式 (`src/group-session.ts`)**：
  - 传统机器人每次发言必须 @ 触发，体验生硬。
  - v0.9.0 引入房间会话机制：一旦机器人在群内被 @ 触发，即在群内激活一个带 TTL（默认 10 分钟）的持续会话上下文。在该时间窗口内，群友后续的自然发言将作为上下文进入会话，无需频繁 @。
- **语境与追问判断 (`src/followup.ts`, `src/addressing.ts`)**：
  - 当机器人在群内发言后，自动开启 90 秒的追随观察窗口。
  - 结合轻量级模型判定接下来的发言是在讨论公共话题还是针对机器人的追问，智能决定是否应答。
- **主动接话与活跃度滑块 (`src/proactive.ts`, `src/engagement.ts`)**：
  - 针对白名单内开启主动接话的群，在未被 @ 时倾听群聊（需累计多条未读有效消息），以可调节的活跃度等级（0-100，涵盖 off, quiet, balanced, active, lively）自主决定是否插话。
  - 设定 5 分钟冷却期与每小时上限，保障群聊不被刷屏干扰。
- **真人质感模拟 (`src/humanize.ts`)**：
  - 动态打字延迟：根据回复字数计算拟真打字时间（`typingMs`）。
  - 思考延迟：根据对方输入复杂度模拟停顿（`thinkMs`）。
  - 随机抖动（`jitter`）与深夜降频（`quietHourFactor`）。

### 5. 多模态视觉与表情包兼容管道 (`src/media.ts`, `src/media-file.ts`)
- **DeepSeek 视觉模型无缝对接**：
  - 支持 JPEG, PNG, GIF, WebP 格式图片的自动识别与 Base64 装配。
  - 严格限制：每轮最多 4 张图片、单张上限 5 MiB、整轮总计不超过 12 MiB。
- **QQ 表情包与 CDN 重定向容灾**：
  - 针对 QQ CDN 复杂的 302/HTTP 跳转，实现受控安全重定向追踪（严格限 3 跳，强制 HTTPS，禁止内网私网地址，防范 SSRF）。
  - 市场大表情动图下载受阻或尺寸超标时，自动回退到同款表情的静态预览图。
  - 结合本地文件缓存（`get_image` 机制），最大化保障视觉输入成功率。
- **隐私保护底线**：
  - 视觉原图上传必须经过用户显式确认同意（Opt-in）。
  - 图片数据仅供当轮模型推理，不存入磁盘会话历史或脱敏日志。

### 6. 账户、财务审计与定点计费 (`src/usage-ledger.ts`, `src/balance.ts`, `src/api-account.ts`)
- **零误差定点计价**：
  - 杜绝浮点数漂移，底层基于 JavaScript `BigInt` 实现以皮元（$10^{-12}$ 元，pico）为单位的定点算术运算。
- **DeepSeek 缓存阶梯计费（Cache-Aware）**：
  - 区分高峰与空闲时段单价，精准匹配官方对于“缓存命中”、“缓存未命中”、“补全输出”的阶梯定价。
- **两阶段可靠记账（Two-Phase Ticket Ledger）**：
  - 发起请求时记录锁定快照，请求完成时结算入账；即使程序异常退出，在途任务亦能如实反映在未完成账本中，防止成本漏算。
  - 支持逐好友、逐群组的独立用量与金额核算展示。

## 四、安全体系与隐私边界

1. **凭证隔离与系统级保护**：
   - DeepSeek API Key 存储于用户级配置文件中，并全程采用 Windows 系统提供的 DPAPI（数据保护 API）加解密，内存中执行脱敏展示，UI 无法反向读取明文。
2. **本地环回限制**：
   - NapCat 服务端口与本地 WebUI 仅绑定 `127.0.0.1`，绝不对公网暴露任何控制端点。
3. **安全 IPC 通信**：
   - 渲染层向主进程发起的 IPC 请求通过 `ipc-origin.ts` 严格校验调用源 Origin，拦截来自非法页面或调试器的恶意注入。
4. **防风控与行为节制**：
   - 严格的频率限制与异常阻断机制，杜绝异常循环死锁导致腾讯 QQ 账号受到官方风控或冻结。
