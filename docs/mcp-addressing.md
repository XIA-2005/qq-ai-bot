# 判断「是不是在跟我说话」+ 去掉句中空格

提交 `b918852`。

## 问题 1：判断消息是否是对自己说的

改之前，群里只有**一个**信号能让机器人认真回复：明确 `@` 它。除此之外全部走「偶尔接话」的候选池，要过冷却、频率、随机判定。

所以有两种情况被漏掉了——而且都是真人眼里明显在跟它说话的：

- **引用回复**：别人引用机器人刚说的话追问一句，不 @。改之前 `reply` 段根本没被解析过，这条消息和路人闲聊没有区别。
- **直接喊名字**：「小夏敬博 这个怎么弄」。

现在三种信号等价，都按直接对话处理（`src/addressing.ts`）：

| 信号 | 判断方式 |
| --- | --- |
| `@` | 原有逻辑 |
| 引用机器人的消息 | 机器人记住自己发出的 message_id（最近 200 条），引用命中即算 |
| 点名 | 连接时从 `get_login_info` 取自己的昵称并匹配 |

不是对自己说的，行为完全不变——仍然走原来的偶尔接话逻辑，由参与度滑块控制。实测：

```
@ 机器人          -> 回复
引用机器人的消息     -> 回复
点名机器人         -> 回复
引用别人的消息      -> 不回复
@ 别人           -> 不回复
路人闲聊          -> 不回复(仅进入偶尔接话候选池)
```

### 一个需要你知道的取舍

中文没有空格，没法可靠地判断「词边界」。`这题问小夏就行` 明显在叫它，但名字两边都紧贴着别的字——和 `今天小夏天气不错` 的结构一模一样。要分开得上分词，太重了。

我选择**中文名字只要出现就算**，代价是 `小夏天` 这类词也会误触发。理由是两种错的代价不对等：被人叫了却装死，正是你反馈的问题；偶尔多答一句只是显得热情一点，而且后面还有冷却和频率限制兜着。英文名字保留严格边界（`bot` 不会在 `robot` 里触发），因为那里边界是真实存在的。

这个取舍写进测试里了，不是隐性行为。

## 问题 2：句中空格

「确实 话都变味了」这种一句里用空格分隔两个短句，是很明显的机器痕迹——真人是按回车的。

现在中文短句之间的空格会拆成两条消息：

```
"确实 话都变味了"      -> 2 条: ["确实", "话都变味了"]
"我去 这是真厉害"       -> 2 条: ["我去", "这是真厉害"]
```

**表示无奈的「。。。」后面的空格保留**，这是你指定的用法：

```
"。。。 你是认真的吗"    -> 1 条
"无语了。。。 算了"      -> 1 条
```

有意义的空格一律不动：

```
"用 npm 装一下"       -> 1 条
"deploy the build"   -> 1 条
"看这个 https://a.cn/b 就懂了" -> 1 条
```

规则：只在空格**两侧都是中日韩文字**时才拆；含 ``` 代码块、`[CQ:`、`http(s)://` 的行整行跳过。同时在全局提示词和群聊提示词里加了对应要求，从源头减少这种输出。
