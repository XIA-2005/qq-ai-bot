# 实时聊天两阶段语境分析（2026-09-27 源码变更）

> 这是源码功能说明，不代表已重新打包或已经在真实 QQ、真实图片、付费模型账单上验收。

## 用户选择与开关

- 默认**关闭** `chatAnalysisEnabled`；旧配置不会自动启用。桌面「回复规则」单独确认后，保存配置才可开启。恢复配置历史时，若会重新开启，也必须再次确认；加密备份导入会关闭该权限。保存配置仍沿用原有的自动回复启停规则。
- 范围是**已获授权的全部实时聊天模型任务**：白名单好友、群 @、持续参与、机器人发言后 90 秒内的追问、主动接话、逐张主动看图。没有触发模型任务的群消息不会因为此开关而被送出。原有白名单、黑名单、群权限、视觉许可、预算与上下文截断规则不变。
- 先请求一次模型输出短 JSON 语境笔记（话题、参与者、承接、意图；最多 256 输出 Token），然后发起独立的回复／沉默模型请求。分析只看该任务本来能发送的**有限文字上下文**；为避免两次上传图片原图，真实图片只附加到最终请求。图片候选若安全读取失败，仍不发起付费判断。分析笔记是不可信数据，放在本次最终请求中、不会作为 QQ 消息发送，也不存入聊天历史或日志；不要求模型输出私密推理过程。
- 最终模型仍能判断保持沉默。**即使沉默也可能产生两次付费调用**；分析出错、超时、响应格式无效或被费用护栏阻挡时，尝试原有回复请求（仍可能被预算阻挡），不使用失败的分析内容。暂停／取消及主动候选过期时立即停止后续调用，不借「失败回退」绕过撤销。
- 两次调用各自通过受跟踪的模型用量／预算路径；真实聊天每分钟请求上限按*实际模型请求*使用滚动窗口，分析与最终请求各占一个名额。额度不足时等待并响应暂停；高峰时回复会比旧模式慢，设置每分钟仅 1 次时第二次调用最早在 60 秒后。预算是应用软件估算，不等于供应商硬性收费上限；未知 Token 或取消请求可能仍有实际费用。

## 源码与离线验证入口

- `src/chat-analysis.ts`：受限 JSON 校验、非权威笔记及分析提示；`src/chat-call-limit.ts`：每次真实聊天模型请求的滚动限流；`src/engine.ts`：统一接入已有模型回复路径；`src/main.ts`：保存及历史恢复的单独确认；`src/backup-archive.ts`：导入撤销开关。
- `ui/index.html`、`ui/app.js`：默认关闭开关、费用／图片发送范围提示、独立确认、历史预览与恢复确认。
- 离线测试：`tests/chat-analysis.test.cjs`、`tests/chat-call-limit.test.cjs`、`tests/startup-rows.test.cjs`、`tests/backup-archive.test.cjs`；浏览器界面桩测试：`tests/chat-analysis.browser.cjs`。使用假消息、假模型、假账户，不读取私人聊天、真实图片或 QQ 登录资料。
