# QQ AI Bot 项目全貌与 v0.8.2 核心功能深度解析

日期：2026-09-21

## 一、项目整体架构与技术全貌

QQ AI Bot 是一个基于 Electron + TypeScript 开发的 Windows 桌面端个人 QQ 智能回复机器人应用。核心定位是基于 DeepSeek 大模型（默认 `deepseek-flash`）为个人 QQ 好友与群聊提供智能化、自动化、可控且低门槛的助理能力。

### 1. 技术栈与核心依赖
- **桌面运行时**：Electron 40 + Node.js 22。
- **协议与通讯**：内置免安装的 NapCat 运行时（OneBot v11 协议），通过本地 WebSocket（`ws://127.0.0.1:3001`）实现 QQ 协议收发；集成 `qrcode` 实现免密码手机 QQ 扫码授权。
- **语言模型**：DeepSeek 开放平台 API，支持 Cache-aware Token 解析、余额查询与单价估算。
- **构建与打包**：TypeScript + `electron-builder`，打包目标为 Windows x64 独立绿色包（`win-unpacked`）。

### 2. 核心架构与模块分工
1. **主进程控制中心 (`src/main.ts`)**：
   - 负责全局生命周期、单实例锁（`requestSingleInstanceLock`）、窗口管理与系统托盘。
   - 统一调度各业务模块，通过安全受限的 IPC 协议（`ipc-origin.ts` 强校验来源 URL）向渲染进程暴露 API。
2. **QQ 协议与登录链路 (`src/login.ts` / `src/onebot.ts` / `src/login-memory.ts`)**：
   - 自动化管理内置 NapCat 进程与工作目录，自动生成端口与凭据。
   - 扫码登录支持设备锁验证、登录态记忆与断线重连；提供风险提示与首次确认机制。
3. **会话调度与消息引擎 (`src/engine.ts` / `src/scheduler.ts` / `src/auto-reply.ts`)**：
   - 实现消息缓冲合并、防刷屏截断、限流排队与上下文记忆管理。
   - 白名单机制严格区分好友（`p:<qq>`）与群聊（`g:<group>`）。
4. **高级会话交互 (`src/proactive.ts` / `src/group-session.ts`)**：
   - 群聊场景支持精准 @ 响应、被动接话及「@ 一次后持续参与」（v0.9.0 引入的房间模式）。
5. **个性化与人设工坊 (`src/persona.ts` / `src/profiles.ts` / `src/preview.ts`)**：
   - 支持素材导入、大模型提炼人设、逐对象独立 Prompt 配置与独立测试试聊通道。
6. **账户与费用审计 (`src/api-account.ts` / `src/balance.ts` / `src/usage-ledger.ts`)**：
   - 提供 API Key 配置、实时余额查询与 v0.8.2 引入的聊天用量/估算金额全流程账本。

## 二、release-v0.8.2 核心功能与技术实现

v0.8.2 的核心命题是 **「聊天累计使用金额（估算）」**，彻底解决了用户在本地跑机器人时“对消耗了多少 Token、花了多少钱缺乏感知和把控”的痛点。

### 1. 业务目标与边界规范
- **明确估算性质**：明确界面所展示金额为基于模型实际返回 Token 与单价的本地估算，非查询 DeepSeek 账户全量历史账单，也不通过余额差额倒推分摊。
- **双层展示维度**：
  - **全局总额**：主窗口运行概览与「用量统计」主页面展示软件累计总消耗。
  - **逐对象分摊**：白名单每一行（每个好友、每个群）均实时展示该对象的独立聊天金额与试聊金额。
  - **非聊天分类**：独立试聊（preview）、验证测试（verification）与人设工坊提炼（persona）独立记账，不混淆进聊天消耗。

### 2. 高精度定点计价算法与 DeepSeek 缓存模型
- **消除浮点误差**：
  - 拒绝 JavaScript 浮点数运算，底层采用 `BigInt` 整数定点计算。
  - 单价统一转换为“百万分之一元”（micro），金额内部以 $10^{-12}$ 元（pico）为单位累计。
  - 界面格式化展示保留 8 位小数；当金额大于 0 但低于 0.00000001 元时，明确标注 `<0.00000001`，避免虚假归零。
- **Cache-aware 阶梯计费**：
  - 严格适配 DeepSeek 官方缓存定价策略（单位：元/百万 Token）：
    - **高峰参考价（默认）**：缓存命中 0.04 / 缓存未命中 2.00 / 输出 8.00。
    - **空闲参考价预设**：缓存命中 0.02 / 缓存未命中 1.00 / 输出 4.00。
  - **单价快照与不可溯及性**：请求发起时即锁定当前生效单价生成 Ticket；后续修改单价仅影响后续发起的请求，历史已记账金额绝不重算。
- **数据缺失的严谨降级**：
  - 当 API 未返回缓存拆分字段时，保守按全部未命中计算，并显式递增 `assumed` 计数（“缓存拆分缺失按全未命中估算”），不虚构缓存命中。

### 3. 两阶段可靠记账与崩溃防护 (`UsageLedger`)
- **Ticket 生命周期机制**：
  1. `begin(context, model)`：在请求发送前即签发 Ticket，在对应 Bucket 中记入 `unknown++`（用量不完整/在途）并增加调用次数。
  2. `record(ticket, usage)`：API 响应完成后更新实际 Token，将 `unknown` 扣减并转入已完成金额。
  3. **中断保护**：若应用在请求过程中发生崩溃、断电、被强杀或网络超时，未完成的请求在重启后仍保留为“用量不完整”，绝不假装零消费或凭空丢失。
  4. **Observer 防漏记**：通过 `completeWithUsage` 的用量监听器，即使模型因为内容安全等原因未返回可用文本，已发生的 Token 扣费依然被真实记录。
- **数据存储与持久化韧性**：
  - 存储路径：`userData/usage-ledger.json`。
  - **原子写入**：先写 `.tmp` 临时文件，校验后通过 `fs.renameSync` 原子覆盖，防止断电导致文件损坏。
  - **容灾熔断**：设置 4MB 文件上限；如果发现文件损坏或非法格式，立即停用统计写入并弹窗警告，坚决不覆盖损坏文件，保护用户历史数据资产。
  - **容量控制**：设置最多 4000 个统计对象桶（Bucket），超量自动归并至 `overflow`（其他历史对象），杜绝内存与磁盘无限制膨胀。
  - **隐私安全**：账本仅记录对象 ID、调用次数与统计数值，绝不落盘 API Key 或聊天文本。

### 4. 界面与交互体验
- **用量统计专属面板 (`ui/usage-ui.js`)**：
  - 顶部指标卡：累计总额、聊天、试聊、验证、人设提炼分类总览。
  - 完整性状态条：展示调用总次数、不完整次数、假设未命中次数与在途请求数。
  - 单价调配表单：支持高峰/空闲一键切换与自定义单价，附带操作风险二次确认弹窗。
  - 历史对象用量表：支持按好友/群筛选，已移出白名单的历史对象仍保留消费痕迹。
- **白名单行实时角标 (`ui/whitelist-rows.js`)**：
  - 在好友/群的每一行输入框下方直接标注：`聊天累计估算 ¥ X.XXXXXXXX · 试聊 ¥ Y.YYYYYYYY`。

## 三、总结与后续版本演进脉络

v0.8.2 是 QQ AI Bot 在商业化与实用化可用性上的关键里程碑，构建了完整的成本可观测性体系。该体系为后续 v0.9.0 的群聊持续参与（房间模式）带来的更频繁交互提供了坚实的费用底座。
