# QQ AI Bot v0.9.6 · 大更新与使用方法

> **发布形式：仅源码。** 此 GitHub Release 没有 Windows 安装器或 `win-unpacked` 更新 ZIP，不含 NapCat、QQ DLL、登录档案、API Key 或私人群聊导出。GitHub 自动提供的 Source code ZIP **不能直接双击仓库里的 `启动机器人.exe` 使用**。Windows 10/11 x64 用户需要自己合法取得与锁文件匹配的本机运行时，再按下文构建完整包。已有用户电脑上的 v0.9.6 完整包未上传公开仓库。此前的 v0.9.3 仅界面安装器也不是此版。

## 相比 v0.9.4 的主要变化

1. **本机群聊历史导出：**桌面侧边栏新增「群聊历史导出」，可导出当前账号可访问的整群消息或指定成员消息；指定成员模式也会遍历整群再筛选。生成 `messages.jsonl`（含原始消息对象／消息段／媒体引用）、`messages.txt` 和 `manifest.json`；只保存引用，**不下载媒体原件**，不调用模型，不向 QQ 发消息。自动在 `%LOCALAPPDATA%\QQ-AI-Bot-Exports\` 新建目录，不覆盖旧结果；支持进度、取消和打开目录。无法证明翻页到历史末端时明确标 `partial`，不冒称“建群以来完整”。v0.9.6 还修正了群号输入框与范围下拉框的顶部及高度对齐。
2. **群聊上下文与知情边界：**常规群回复取最近 30 条与过去 24 小时两个范围中较大的集合，缓存至多 100 条，模型请求上下文至多 8,000 字符；超限优先保留新消息和引用并提示截断。夜间整理要携带群友 QQ 号与群名片映射，必须同时开启**全局夜间整理、该群夜间整理、该群映射授权**；旧全局开关单独开启不扩大披露范围。
3. **可选的主动看图与两阶段聊天：**「逐张主动看图」默认关闭，需在回复规则单独确认，还须该白名单群开启主动接话且允许视觉上传。每张普通群图可成为潜在的**付费判断**候选，没有额外图片专用逐群时间冷却；仍受全局限流、预算和发送约束，并不保证每张都发言；若点评，最多一行、30 字符。「每次聊天先独立分析」也默认关闭；授权后先付费分析有限文字语境，再发起原回复／沉默请求，沉默也可能产生两次费用。分析失败时尝试原请求，仍受权限与预算约束；图片只随最终请求上传。
4. **可检查的内容与数据恢复：**新增表情包预设情绪的人工分类，未经分类的旧/新表情包不会仅凭名称推断情绪；增加配置历史预览与恢复。桌面可创建／预览／导入密码加密 `.qqaibak`，覆盖配置、API Key、人设／历史、群资料、风格样本及 **QQ/NapCat 登录档案**，不包含手机设备令牌。每次手输密码，以 scrypt + AES-256-GCM 加密；导入前认证、预览、确认并保持自动回复暂停。备份限 2 GB／10,000 文件；密码丢失无法解密。**未用真实账号做恢复演练**，请先在测试副本验证。
5. **明确的版本入口：**完整本地打包会写哈希清单并验证项目根目录 `启动机器人.exe` 实际选择本版；坏包不能靠旧版回退冒充发布成功。v0.9.5 是上述功能的首个本地完整包，v0.9.6 增补历史导出表单对齐。运行中的旧程序不会自动升级，旧快捷方式也不会改指向。

## 从本 Release 源码自行使用（Windows x64）

1. 安装 **Node.js ≥ 22.12**，从本 Release 的 Source code 下载源码，或运行 `git clone https://github.com/XIA-2005/qq-ai-bot.git` 后 `git checkout v0.9.6`。使用已有工作目录时，先保存自己的修改和数据；**不要用 Git 清理或覆盖个人登录档案、导出文件**。
2. 自行从有权使用的可信来源准备完整且与 [`scripts/vendor-runtime.lock.json`](https://github.com/XIA-2005/qq-ai-bot/blob/v0.9.6/scripts/vendor-runtime.lock.json) 匹配的 Windows NapCat／QQ 本机运行时，放在源码目录 `vendor/napcat-runtime/`。本项目**不提供腾讯 DLL、QQ 组件或规避许可的下载途径**；不要为通过校验而修改锁文件或从陌生人处拼接文件。只有源码而没有此运行时，不能登录 QQ 或导出历史。
3. 在源码目录的 Windows 终端运行：

   ```bat
   npm ci
   npm run preflight:runtime
   npm run ci:offline
   npm run pack:win
   ```

   预检不通过就不要打包。`pack:win` 生成 `release-v0.9.6\win-unpacked\`、写哈希清单、验证根启动器选包并自动生成发布验证摘要。只有从源码跑自动化时才需要 Node；用已构建的完整目录不需要 Node。想额外运行浏览器测试，可先安装 Chromium：`node node_modules/playwright-core/cli.js install chromium`，再执行 `npm run test:browser`。
4. 如旧程序还在运行，先在**托盘右键「彻底退出」**，再双击**项目根目录** `启动机器人.exe`。不要单独复制 `QQ AI Bot.exe`；需保留完整 `win-unpacked` 目录、`resources/napcat-runtime` 和 `launch-manifest.json`。在「运行概览 → 当前实际运行包」核对版本与完整路径指向 `release-v0.9.6`。仅下载 GitHub 源码、没构建包时，启动器不会凭空生成桌面程序。
5. 在「QQ 连接」使用自己的测试 QQ 扫码登录；在「模型设置」填入自己的 DeepSeek API Key；在「回复规则」设置好友／群白名单、阅读并确认群追问和费用边界，再保存配置。**成功保存可能解除手动暂停**，满足连接、密钥、白名单及同意条件后会尝试开启自动回复；如只想做导出，请保存后再次点击「暂停回复」，但保持 QQ 登录在线。谨慎决定是否另外开启视觉、逐张主动看图、夜间 QQ 号映射或两阶段分析。

### 群聊历史导出与备份怎么用

- 在已登录的桌面窗口打开「群聊历史导出」，输入**你有权处理的**群号，选择「整群所有成员」或「指定成员」（再填成员 QQ 号），点击「开始导出」并确认隐私提示；指定群**无需**加入自动回复白名单。完成后看 `manifest.json` 的状态，`partial`／`running` 均不可当完整备份。输出是含聊天正文、成员号及可能有时效媒体链接的**未加密明文**，不要提交 Git 或上传。详见 [导出操作与分页边界](https://github.com/XIA-2005/qq-ai-bot/blob/v0.9.6/docs/group-history-export.md)。
- 备份请在「桌面设置」先暂停回复、停止本软件托管的 QQ 登录，再手输至少 12 字符密码创建 `.qqaibak`；在恢复前先用可信文件和密码预览，再确认导入。恢复后检查账号、预算和白名单，重新确认自动回复及逐群/逐张/两阶段权限；手机既有配对**不会**因导入自动撤销，应按需在桌面单独撤销。勿分享含登录档案的备份或密码。

## 升级、测试与重要限制

- 此 GitHub Release **没有可供应用内「下载并安装」的 ZIP／SHA-256**。已有完整本地包用户须在自己的 Windows 工程里按上述合法运行时和构建步骤生成新目录，再用根启动器切换；不能把 GitHub 的 Source code ZIP 当作应用更新包。历史 v0.9.4 Release 曾含第三方运行时，本次**不延续公开上传**。
- v0.9.6 在本机 Windows 完整打包并校验根启动器选包；离线 Node 测试 **420/420**、Chromium 假服务/界面测试 **8/8**。这些测试不调用付费模型。对获授权真实群使用 NapCat 共用导出服务的整群及成员筛选已通过结构核验，但两种结果均为 **`partial/pagination-stalled`**，无法证明完整历史；**未以真实 Electron 窗口人工点击按钮、未实测真实 QQ 登录档案恢复或真实 DeepSeek 账单**。使用前请在测试账号、可告知成员的群及备份副本上再验收。
- 默认费用护栏是软件估算而非供应商硬上限；主动图片及两阶段任务即使不发言也可能产生费用。个人 QQ 自动化可能导致风控或封号。手机远程仍需自己配置受控的 HTTPS 域名与隧道，仓库示例域名不可直接用。更多边界见 [当前版本指引](https://github.com/XIA-2005/qq-ai-bot/blob/v0.9.6/docs/current-release.md) 和 [本机发布验证摘要](https://github.com/XIA-2005/qq-ai-bot/blob/v0.9.6/docs/releases/v0.9.6.md)；后者所列包哈希只对应维护者本机包，**不是** GitHub 可下载资产的校验码。
