## 直接启动

双击根目录 `启动机器人.exe`；它需要已构建的 `release-v0.9.2/win-unpacked/QQ AI Bot.exe` 及完整清单，实际运行版本以桌面概览为准。不能只复制 EXE：必须保留完整的 `win-unpacked`、`resources/napcat-runtime` 和 `launch-manifest.json`，否则启动器拒绝。已有完整包日常启动不需要 Node.js；从源码构建则需要 Node.js 与经过预检的运行时。
关闭窗口默认收起到系统托盘；需要停止软件时请右键托盘选择「彻底退出」，或在「桌面设置」中退出。开机启动默认关闭，需在桌面设置中单独确认。

## 使用步骤

1. 如果旧版仍在运行，请先退出，再双击根目录 **`启动机器人.exe`**。它会验证清单并选择版本最高的完整包。原有 API Key、白名单与主动接话设置继续沿用。
2. 在「模型设置」保存 DeepSeek API Key，模型固定 deepseek-flash；在「回复规则」逐行填写好友及群白名单，一个账号或群号一行，可添加、删除行。空行忽略，重复号码去重，每类最多 200 行。支持粘贴多个号码自动拆行。
3. 每次打开软件都会等待 QQ 就绪后自动开启回复，旧版关闭的自动回复选项也会升级为开启；旧版同意不含 90 秒群追问告知，升级后须在 Windows 主窗口重新确认消息范围、额外模型费用与账号风险；不会扩大白名单或开启主动接话。
4. 进入「QQ 连接」，点击登录并确认风险；手机 QQ 切换到希望托管的另一个账号后扫码、确认和完成官方设备验证。
5. 登录成功、配置齐全且已确认时，自动开启白名单回复。仍可以随时暂停。保存配置、应用人设或清空记忆后保持暂停，可手动开启，也可重新登录后按设置自动开启。
6. 想从素材提炼人设时，进入「人设工坊」，导入或粘贴素材，生成后先预览，再确认应用。无需训练模型。

手动暂停后，断线重连不会擅自恢复；未手动暂停的运行会话可在重连后按设置恢复。登录前若缺少 API Key、白名单或本版本的知情确认，不发送回复。暂停只影响本次运行，完全退出再打开会重新自动开启。未记住登录账号或 QQ 要求验证时，需要先登录；等待状态不代表已经在发消息。
模型验证只有点击并确认后才发起一次可能计费的 API 请求。群白名单默认可被 @ / 点名 / 引用；机器人发言后的 90 秒内，任何成员的未 @ 消息还可能连同近期群聊文字送模型判断，判断和回复均可能计费（积极度 0 也不关闭）。持续参与或主动接话需要单独开启。

## 扫码与账号

- 软件管理内置 Windows x64 QQ/NapCat 运行时，随机端口和令牌自动生成。
- 本机 WebUI 和 OneBot 均只监听 127.0.0.1，不开放公网。
- 二维码在本地生成，不把登录链接交给第三方二维码网站。
- 已开启记住账号时，启动软件会用明确记住的账号尝试恢复登录；否则先手动扫码。不会读取 QQ 密码或绕过官方设备验证。
- 不修改、注入或关闭你平时使用的桌面 QQ 程序。
- 运行时使用单独的工作目录及子进程环境，但不承诺与 Windows 原生 QQ 数据实现完全隔离。
- 「停止登录服务」及彻底退出软件会终止本软件启动的运行时。关闭窗口默认只收起到托盘，不会停止回复。此操作不等同于从手机 QQ 的设备列表撤销授权。
- 需要换账号时，先停止登录服务，再重新扫码；手机务必切换到目标账号。

## 数据与隐私

- DeepSeek API Key 用 Windows 用户级 DPAPI 加密，不会回显。
- NapCat 需要在自己的本地 JSON 中读取自动生成的接口令牌；这些不展示在 UI 或转发至外网，不代表使用 DPAPI 加密。
- 配置及 QQ 运行数据位于 Electron userData 下，通常 `%APPDATA%/QQ AI Bot/`。
- 机器人上下文、脱敏日志仅内存保存。QQ 内核自身可能保存会话/设备数据，不承诺磁盘完全没有 QQ 数据。
- 自动回复会把文字与必要上下文发送给 DeepSeek；默认追问还可能发送同群其他成员的近期文字，即使不发 QQ 消息仍可能产生模型费用，请提前告知相关成员。
- 默认最多 6 轮记忆，连续文字静默 1.5 秒后合并回答（最多等 5 秒）；最多 3 个独立会话并发，每个私聊或群两次请求启动至少间隔 5 秒，每分钟共享 10 次请求，最多 20 个等待任务、60 秒等待时限。
- API 和消息发送失败不自动重试，避免重复回复；暂停不能撤回 QQ 已接收的发送动作。

## v0.3.0：群聊主动接话

升级时请先退出旧版窗口，再通过根目录启动机器人.cmd 启动。旧版 release-v0.2.0 保留，原有配置和加密 API Key 继续使用；本功能默认关闭，不会自动扩大回复范围。

开启步骤：
1. 在「回复规则」的群白名单中添加群号。
2. 勾选「开启群聊主动接话」，在下面的专用列表中填写允许主动参与的群号（必须是群白名单的子集）。
3. 保存配置，然后在运行概览手动开启自动回复。保存会暂停回复，不会退出 QQ 登录。

行为：
- 不需要 @。至少累积 3 条新的有效群文字后才考虑判断；每群判断最多每分钟一次，仍受全局每分钟 API 请求上限控制。
- 每次判断用同一个 deepseek-flash 请求完成是否参与及短回复生成。不合适、输出格式无效或聊天已更新时保持沉默；不是到点一定发言。
- 每群两次主动发送尝试至少间隔 5 分钟；滚动一小时最多 6 次。正常 @ 回复不受此主动发言额度限制。
- 发送结果不确定时不重试，并保守计入额度。暂停/保存配置不会清除本次运行的限频额度；退出软件后内存限频状态重置。
- 主动发言只发送短纯文本，不额外 @ 群友。有人 @ 机器人时，优先保留原来的直接回复行为，并使旧的主动接话候选失效。
- 不处理自己、忽略名单、过期事件、带 @ 的普通群对话，以及非文字内容。建议将其他机器人加入忽略名单，减少机器人间互相接话。
- 每群最多保留 12 条文字片段，每条最多 600 字符；判断只使用最近 5 分钟的内容。仅在内存中保留，不混入私聊记忆，也不记录聊天正文。暂停时清空主动接话上下文。
- 没有新消息就不触发，不会定时自言自语。判断期间又有新聊天时丢弃旧答案，避免迟到插话，因此活跃群里实际发言可能少于上限。

隐私与费用：开启后，指定群的普通聊天文字也会发送至 DeepSeek 用于判断；即使最终保持沉默，判断仍可能产生费用。请先告知群成员，勿在不适合分享聊天内容的群中开启。

验证：36 项自动化测试覆盖新旧逻辑；真实 QQ 群聊的自然程度及模型判断需要用户实际使用确认，测试不冒充已完成真实群发言验收。

新版实际 EXE 验收：artifacts/proactive-packaged-acceptance.json；界面截图：artifacts/proactive-rules-v0.3.0.png。独立配置中验证开启、保存、关闭、越界群拒绝、默认暂停和 900px 窗口布局；没有登录 QQ、发送消息或调用付费模型。

## v0.4.0：人设工坊与登录后自动回复

### 人设提炼

- 支持粘贴 QQ 聊天导出、网页正文、小说片段；或导入 UTF-8 编码的 TXT、Markdown、JSON 文件。不会自动读取 QQ 数据库或网站。
- 素材 50–60000 字符，单文件最多 512 KB。长篇小说请选代表性片段；群聊记录请保留说话者，并填写目标昵称/角色，避免混淆多个人的风格。
- 以每段 6000 字符进行分析，再汇总为全局系统提示词，共 2–11 次 DeepSeek 请求。显示进度，可以取消；已发出的请求仍可能计费，失败/取消不会替换原提示词。
- 提炼期间暂停聊天回复。草稿可编辑，只有确认应用才替换系统提示词。应用或恢复时清空对话记忆、保持暂停。
- 备份上一版系统提示词，支持恢复；恢复时当前版本成为新备份（不是无限版本历史）。
- 原素材与未应用草稿只保留在当前窗口/请求内存，不写入配置与应用日志。应用后的人设及其上一版会保存在本地配置中，和原有系统提示词一样不是 DPAPI 加密字段；API Key 仍由 DPAPI 加密。
- 请求直接发到官方 DeepSeek。请只提交有权使用的资料，并在提交前删除隐私、账号密码及联系方式。提炼规则提示模型避免私人身份、大段照抄与真实身份冒充，但不是可靠的自动脱敏工具，应用前必须检查。
- 这是提示词提炼，不是模型权重训练，也不是知识库。不会让 AI 记住整本小说或完整聊天史。实际风格效果取决于素材与模型输出。

### 默认自动回复的边界

autoReplyOnLogin 默认 true，旧配置升级也启用此选项，但 autoReplyConsent 默认 false：不会替用户虚构首次同意。首次保存配置、扫码登录或手动开启时确认后才记住许可。没有登录事件不会仅因启动软件就发送消息。
手动暂停/保存配置/提炼或应用人设会阻止本次会话的自动恢复；用户显式重新登录或手动开启后才解除。好友与群白名单、忽略名单、冷却、队列、上下文隔离和主动接话限频继续生效。

### 验证结果

47 项自动化测试通过，含分段与汇总、取消后的迟到结果丢弃、长度限制、旧配置迁移、首次同意、自动启动条件、暂停后不因重连恢复，以及 OneBot 就绪回调。
实际 v0.4.0 EXE 在独立临时配置下通过：TXT/MD/JSON 导入、自动回复确认取消/保存、人设应用与备份恢复、素材不出现在配置/日志、900px 布局和集成运行时可用性检查。

## v0.5.0：记住登录账号与 EXE 启动入口

### 保持 QQ 登录

- 「QQ 连接」页新增 **记住此账号，启动软件时恢复登录**（默认开启）。首次登录成功后，软件会在本机 `login-memory.json` 中只记录 QQ 号码，不保存密码、令牌或聊天内容。
- 启动软件时，如有记住的账号，会自动用该账号的本地登录资料尝试恢复登录，无需重新扫码。
- 升级到 v0.5.0 后首次启动，会读取内置 QQ 运行时目录中已有的账号资料文件名（仅账号号码），自动作为待恢复账号。
- 恢复登录依赖 QQ 服务端是否仍认可这台设备。**账号在别处登录、被挤下线、QQ 要求安全验证或本机资料过期时，仍需扫码或在手机确认**；这是 QQ 官方规则，软件不会也不应绕过。
- 恢复失败时只会退回扫码，不会自动换账号。关闭「记住此账号」后不再自动恢复，也不会删除 QQ 运行时的本地资料，更不会撤销手机上的设备授权。
- 「切换账号（扫码）」会停止当前连接、清除记住的账号并显示二维码；不影响你平时使用的 QQ 客户端。

### 直接双击 EXE（v0.5.0 历史记录；当前入口见本页顶部）

- 根目录 `启动机器人.exe` 就是启动程序，双击即可，无控制台窗口；出错时会弹出提示。
- 本段仅记录旧版 v0.5.0 的打包路径，不代表当前可执行包；现在请通过根目录启动器按清单选择最高版本。
- 启动器按版本号自动挑选最新的 `release-v*.0` 目录，因此以后升级不必重新编译启动器。

54 项自动化测试通过，新增记住账号的持久化、关闭后清除、切换账号、账号格式与损坏数据校验、恢复目标只使用明确记住的账号（不含密码）。
实际 v0.5.0 EXE 在两个独立临时配置下验收通过：无记住账号时不会启动 QQ 运行时；记住开关经真实 IPC 写入本机文件且不影响现有配置；有记住账号时启动即进入恢复流程；人设应用/恢复、900px 布局正常。
证据：artifacts/session-packaged-acceptance.json；截图：artifacts/login-memory-v0.5.0.png。启动器另以替身程序验证只会启动最新版本目录。
自动化验收没有真实扫码登录任何账号，没有发送 QQ 消息，也没有调用付费模型。恢复登录的实际成功率取决于 QQ 服务端对这台设备的认可状态。


## v0.7.0：连续消息合并与会话调度

- 「回复规则」新增合并等待时间（默认 1500 毫秒，0 为关闭）和并发会话数（默认 3，可设 1–5）。旧配置自动采用默认值。
- 一个好友连发的文字，或同一人在同一群 @ 发起的一轮，在最后一条后静默 1.5 秒再统一回答；从首条起最长 5 秒，最多 20 条、8000 字符。达到批次上限后后续消息进入新批次，不截断已经接收的文字。
- 群内不带 @ 的补充只在同一人已经发起且尚未封口的合并窗口内接收；其他人、其他群、@ 别人或窗口结束后的普通聊天不会被当作直接回复。
- 生成中的补充留到下一轮，上一轮的成功回复会进入下一轮记忆。不会因补充而反复重调付费模型。
- 不同好友或不同群可以并行；同一私聊、同一个群从生成到发送完成都占用同一调度通道，不会乱序交叉发送。群内不同人的记忆仍分开。
- 冷却和每分钟限额改为等待；排队满时拒绝新任务，等待超过 60 秒的旧任务过期。队列包含合并中的批次，避免无限堆积。
- 直接回复优先于尚未开始的主动接话；同群新 @ 会使旧的主动接话候选失效并尝试取消请求，仍不重试结果不确定的发送。
- 暂停会清空合并及排队任务、取消全部在途模型请求；已经交给 QQ 的发送不能撤回。不理会取消的提供方返回旧结果时也不会再发送。
- 运行概览显示正在处理、等待、合并中的数量，页脚显示合并和过期计数。计数仅针对本次运行，日志不记录聊天正文。


## v0.8.0：对象独立设置、试聊与桌面常驻

### 每个好友或群独立设置

- 白名单每行增加备注、启用状态和「设置」。备注随白名单保存；已保存号码的启停与对象设置单独立即生效。
- 人设默认继承全局，可设置独立提示词、回复长度和记忆轮数；群可继承默认主动接话策略、常规回复（仍保留短时追问）或独立允许主动接话。新开启的主动接话仍需确认费用及发送范围。
- 全局修改不会覆盖独立人设；独立长度上限仍受全局最大 Token 限制。简短/正常/详细是风格指导，不承诺精确字数。
- 修改一个对象的有效配置，只清理该对象的排队任务、在途模型请求和记忆；修改备注不清记忆。其他对象继续运行。
- 保存全局配置仍暂停本次自动回复，但只清除有效配置发生变化的对象记忆。人设工坊应用或恢复全局提示词不覆盖独立提示词。
- 关闭某个对象会立即阻止后续回复、清理待发任务；已交给 QQ 的发送无法撤回。删除白名单行会一并删除该对象独立配置。

### 独立试聊

- 选择已经保存的对象，显示实际采用的系统提示词、来源、记忆轮数和输出上限；已停用对象也可以试聊，但不会被自动启用。
- 只有明确点击并确认后才调用 DeepSeek，可能计费；返回内容只显示在试聊区，绝不发送到 QQ，也不影响真实聊天记忆。
- 试聊历史仅在内存中保留最近 12 轮，发送给模型的轮数遵循目标配置；切换对象、清空、目标有效配置变化或退出应用会清理相应试聊上下文。
- 试聊可取消；忽略取消的模型返回迟到内容也不会应用。失败不会把不完整回合写入成功历史。
- 显示请求耗时和 API 实际返回的输入/输出/总 Token；接口没有提供时显示未提供，不虚构成本。
- 试聊与真实会话可并行；试聊单独最多一个请求、每分钟不超过 min(全局 perMinute,10)，清空试聊不重置频率额度。

### 托盘、开机启动与通知

- 「桌面设置」可选择关闭窗口后收起到托盘（默认开启），托盘菜单提供打开、暂停、恢复、彻底退出。托盘失败时关闭窗口仍能正常退出。
- 开机启动默认关闭，只在明确确认后修改 Windows 登录启动项，指向当前版本的 EXE；从开机入口启动后收起到托盘。未打包或独立测试配置不能修改系统启动项。
- 更新版本或移动文件夹后，请重新在当前版本保存开机启动设置，确保 Windows 指向仍存在的 EXE。彻底退出不会自动关闭已明确启用的开机启动。
- QQ 已连接后掉线持续 5 秒触发提醒；短暂闪断不提示，掉线通知间隔至少 2 分钟，已提示过的连接恢复后通知一次。主动停止登录、切换账号和退出不会被当作掉线。
- 提醒不包含聊天正文或账号信息；Windows 通知权限、勿扰模式等可能影响实际展示。
- 桌面偏好保存在 userData 下 desktop-settings.json，仅包含关闭到托盘和提醒开关；开机启动显示 Windows 的实际状态，不读取账号密码。


## v0.8.1：API 余额与连接状态

- 在「模型设置 → API 账户与连接状态」点击「查询 / 刷新余额」，通过 DeepSeek 官方只读接口获取总余额、赠送余额、充值余额、币种和查询时间。余额按原始精度显示，不跨币种相加、不估算成本。
- 查询只使用已经保存的 Key；未保存的密钥或接口修改会提示先保存。查询不会发送聊天内容，不发起模型生成，也不会暂停自动回复；不会在后台自动轮询余额。
- 刷新失败会显示具体错误。已有结果保留，但明确标记为旧结果；从未查询成功时不显示虚构的零余额。调用模型后余额应再次刷新，不是实时账单。
- 模型状态现在由所有实际调用更新：自动回复、独立试聊、手动验证，以及现有的人设提炼调用。普通白名单、人设或参数保存不再重置状态。
- 重启后保留同一 Key / 接口 / 模型的历史成功或失败记录，并明确显示“上次调用成功/失败”，不把历史记录当作本次已验证。首次升级没有历史记录时显示“已配置，待验证”，不能凭空补成成功。
- 更换或删除 Key、接口或模型会清除原状态和余额；旧请求迟到结果不能覆盖新账户。更换 API 配置也会清空独立试聊，避免混用不同凭据的返回结果。
- 余额查询成功只说明该次账户查询成功，不会冒充模型验证。手动验证仍需确认一次可能计费的短请求；无需为更新状态额外付费验证，正常回复或试聊成功也会更新状态。
- `api-status.json` 只保存配置身份摘要、调用成功/失败时间与脱敏错误，不保存明文 Key、聊天内容或余额。余额只留在内存中，重启后需重新查询。

## v0.8.2：累计使用金额（估算）

- 「运行概览」显示本软件累计人民币估算金额；「用量统计」按真实聊天、独立试聊、手动验证、人设提炼分开显示，白名单每行也显示该好友/群的真实聊天和试聊估算。
- 群费用包含该群所有成员触发的模型调用，主动接话判断即使最终沉默也计入。模型已返回用量但 QQ 发送失败或回复被取消，依然计入这次模型用量；不是按成功发送条数计费。
- 从升级后的第一次请求开始记录，不追溯旧版本费用。跨重启、改人设、清聊天记忆、删白名单、更换或删除 Key 都不清零，软件总计包括所有曾在本软件使用的 Key。
- 金额按接口返回的输入、输出、缓存 Token 与请求开始时的保存单价计算，使用整数定点累加；输出文本被截短不减少模型已产生的用量。
- 默认参考 2026-09-21 DeepSeek Flash 人民币高峰单价：缓存命中 0.04、未命中 2、输出 8 元/百万 Token。可选空闲参考价 0.02/1/4 或手动填写；不会自动识别空闲时段、节假日和账户优惠，因此估算可能高于实际扣费。只按人民币参考价估算，不换算美元账单。
- 单价修改仅影响后续开始的请求，不重算历史金额。价格来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/
- 缺少完整用量、失败、中断的请求列为“用量不完整”，金额只显示已知部分，不把它们当作免费。已返回总输入/输出但缺少缓存拆分时，按输入全未命中估算并单列次数。实际费用以 DeepSeek 账单为准。
- 请求开始前先记录为用量不完整；完整用量返回后再补入金额，防止进程中断时把在途请求误标为零消费。余额查询不算模型请求。
- `usage-ledger.json` 保存对象号码、汇总 Token/估算金额和估算单价，不保存聊天正文或 API Key。已移出白名单的历史对象仍可在统计页查看；分组达到 4000 桶后新增对象归入“其他历史对象”，软件总数仍保留。
- 统计文件损坏时不会覆盖原记录，页面明确提示统计不可用；写盘失败会提示可能丢失未保存记录，不影响聊天功能。

## v0.9.0：群聊 @ 一次后持续参与

- 在「回复规则 → 群白名单」的独立设置里，把某个群设为「@ 一次后持续参与」：群内第一次明确 @ 之后，机器人一直参与这个群的聊天，其他群友不需要 @ 也能接着聊，回复不再只针对唤醒者。
- 参与期间由模型按最近群聊内容判断是否要说话，不合适时保持沉默；判断和回复都是真实请求，按该群计入累计金额。
- 房间上下文按时间排列，只以「成员1 / 成员2…」代称，机器人自己的发言标为「机器人」；不保存真实昵称，不读取历史聊天，内存中最多保留最近 16 条、每条 400 字符。
- 别人 @ 某个群友的消息只作为房间上下文记录，不会单独触发模型请求；@全体、纯图片、超长文本和忽略名单里的成员既不会进入上下文，也不会延长参与。
- 群里冷场后自动结束：默认 10 分钟没有人发言即结束，之后需要重新 @，或由它自行判断加入。窗口可在回复规则中改为 1–120 分钟，改动对已经开启的群立即生效；机器人自己的发言不会延长窗口。
- 「@ 一次后持续参与，并允许自行加入」在基础模式上额外允许它在合适的群聊里自行加入，加入成功后同样持续参与；原来的一次性判断行为保留为「允许主动接话（每次单独判断）」。
- 明确 @ 会丢弃该群仍在排队的判断任务，但不会打断已经开始的生成；正在生成的回答仍会正常发出，也不会重复回答同一条消息。
- 暂停、清空对话、完全退出、把对象停用、移出白名单或改回「常规回复」都会立刻结束持续参与并清空该群房间状态，但不关闭之后正常发言产生的短时群追问。持续参与不写入按发言人区分的记忆，改用群聊上下文。
- 回复发送给整个群，不会 @ 任何群友；明确 @ 机器人的那条回复仍会 @ 提问者。状态里只显示群号、成员数、条数、回复次数和预计结束时间，不含聊天正文。
