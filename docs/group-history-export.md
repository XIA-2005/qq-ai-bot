# 在桌面软件中导出 QQ 群可访问的历史

> 桌面入口和命令行共用 `tools/export-group-history.cjs` 的只读分页与状态清单。只读取**当前登录账号可访问的指定群**，不向 QQ 发送消息、不请求 DeepSeek、不下载图片／语音／视频／文件原件。已对获授权的真实群通过本机 NapCat 验收共用服务链路；两种模式均为 `partial/pagination-stalled`，不能当作完整历史。**真实 Electron GUI 手动点击尚未验收**。

## 桌面软件内一键导出

1. 在本机桌面版「QQ 连接」登录并保持 NapCat/QQ 在线；如不希望机器人在导出时回复，先点击「暂停回复」，**不要停止 QQ 登录服务**。
2. 在侧边栏打开「群聊历史导出」，输入群号，选择「整群所有成员」或「指定成员」（后者还需输入成员 QQ 号）。**无需把该群加入自动回复白名单**；请只填写你有权处理的群和成员。
3. 点击「开始导出」，阅读一次性隐私确认并确定。界面显示已扫描页数、群消息条数和实际导出条数；可取消，完成后可点「打开导出目录」。每次自动在本机 `%LOCALAPPDATA%\QQ-AI-Bot-Exports` 下新建私人目录，不覆盖旧文件；不会把连接令牌交给界面或提供手机远程触发接口。

导出过程中保持 QQ/NapCat 在线。取消、断线、上限或无法确认游标末端时，界面与 `manifest.json` 会明确提示“部分导出”；不要把这些文件当作完整结果。关闭软件时会先取消并尽力写入 `partial` 状态；异常强制终止后也可能仍留 `running`，须按未完成处理。脚本默认上限为 20,000 页、两个输出文件合计 2,048 MiB。桌面版固定这些保守上限，如需调整，可使用下面的命令行参数在新目录重新导出。

## 命令行脚本：使用前

1. 在 Windows 主机安装 Node.js ≥22 和项目依赖（项目目录执行 `npm ci`）。使用桌面版时，先启动 QQ AI Bot 并让 NapCat/QQ 成功登录；**如果不想机器人自动回复，先点击「暂停回复」**，不必停止 QQ 登录服务。
2. 在 `D:\QQ-AI-Bot` 打开终端，以下两种模式分别一条命令：

```bat
node tools/export-group-history.cjs --group 123456 --all
node tools/export-group-history.cjs --group 123456 --member 234567
```

上面 `123456`、`234567` 都是**虚构占位号**，请换成你有权导出的真实群号、成员 QQ 号；在 Windows 终端不要输入 `<`、`>` 尖括号。`--member` 也可写 `--uin`。指定成员模式仍需遍历该群的历史，**不能**因为中间几页没有该成员的发言就提早结束；即使成员已退群，只要历史中仍有其 QQ 号且接口返回，仍可匹配。群号与成员号均作为字符串处理，避免无意转换为浮点数字。

脚本优先从本机 `%APPDATA%\QQ AI Bot\qq-profile\napcat-work\config\onebot11.json` 自动发现该软件当前使用的**随机本机 WebSocket 端口和令牌**。如果你使用另一套 NapCat，可用 `--url ws://127.0.0.1:<端口>`，并在**当前进程的环境变量**中配置 `NAPCAT_ACCESS_TOKEN`；不要在命令行参数、URL、聊天或截图中暴露令牌。仅允许 `ws://` 本机回环地址，无远程 WebSocket 和重定向。如应用数据目录不同，可加 `--profile-dir <用户数据目录>`。

## 输出与“完整”的边界

默认新建 `%LOCALAPPDATA%\QQ-AI-Bot-Exports\group-...`，也可用 `--out <尚不存在的目录>` 指定私人目录。**不覆盖已存在目录**。输出如下：

- `messages.jsonl`：每行一条；`raw` 保存 NapCat 返回的**完整消息对象／原始消息段**，另外标注 `group_id`、`user_id`、`message_id`、时间及可读文字。不修改原始 `raw`，媒体保留文件 ID、摘要、可能返回的 URL 等引用。
- `messages.txt`：带 UTC 时间、发言人、QQ 号、消息 ID 的可读版；换行转为 `⏎`，非文字类型显示 `[图片]`、`[语音]` 等提示。它**不是**消息段的无损备份，以 JSONL 为准。
- `manifest.json`：登录账号、群号、模式、已扫描页数／消息数、去重数、最早／最新时间、输出顺序、终止原因以及是 `available-range-exported` 还是 `partial`。

文件按**新到旧**写入，因此可边抓边落盘，避免把整群消息放在内存里。导出器读每页最多 50 条；只有翻到序号 1，或首次查询连续两次确认无可见消息，才标注“接口可访问范围已导出”。已有消息之后 NapCat 报“游标消息不存在”**无法区分真正的历史末端与游标失效**；返回空的解析页也不能证明已到末端。这两种情况都会标注 `partial`、返回非零状态，保留已导出的记录供核对。**即使标注了接口可访问范围已导出，也不等于从建群以来无缺页**：离线期间的消息、撤回消息、QQ 客户端未保留的数据、历史分页接口的局限，脚本无法凭空补齐。合并转发内容不会另行递归下载；媒体原件不会下载。可参阅 [NapCat `get_group_msg_history` 实现](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/go-cqhttp/GetGroupMsgHistory.ts)。

若网络／权限／翻页游标异常，或超过默认 **20,000 页／两个输出文件合计 2,048 MiB**，脚本返回非零状态，保留已导出的文件并将 `manifest.json` 标为 `partial`，**不会谎称完整**。可用 `--max-pages <数>`、`--max-mib <数>`、`--delay-ms <毫秒>` 调整后在**新目录**重试。强行中断也可能留下 `running` 状态文件，不得当作完整结果使用。

## 隐私与验证

原始消息可含所有群成员的 QQ 号、群名片、聊天正文及**可短期访问的媒体链接**；不要提交 Git、共享给他人或上传云盘，做好本机访问权限及群成员知情。桌面入口和独立脚本均不受机器人的“回复白名单”开关控制，**请仅导出你有权处理的群和成员记录**。

离线测试：`node --test tests/group-history-export.test.cjs`，使用假的本机 WebSocket、假群号、假消息和假令牌；没有读取项目现有 `artifacts/qq-history/` 或私人聊天导出，也没有连接真实 QQ。需要在已获授权的测试群人工核对 NapCat 的历史上限、翻页顺序与实际条数。
