# 机器人发言后，由模型判断下一条是不是在回应它

> 2026-09-23 更新：本页原为功能设计记录；现有 v0.9.1 仍默认保留 90 秒追问，但**判断命中本身不续窗**，只有成功发出新消息才重开；暂停和清空会关闭窗口，旧版同意需在 Windows 重新确认费用范围。当前说明见 [v0.9.1 P1 交付记录](p1-repair-release-0.9.1.md)。

提交 `2af864b`。

## 你指出的问题

之前判断「是不是在跟我说话」只有三个硬信号：`@`、引用、点名。但最常见的情况恰恰不带任何信号——**机器人刚说完话，下一条就是冲它来的**：

```
机器人：我觉得应该先看文档
群友：  哪个文档啊 我没找到      ← 明显在问机器人，但没 @
```

改之前这条消息的真实去向（已复现确认）：掉进「主动接话」的候选池，而那个提示词开头第一句就是 **「你正在观察群友聊天，没有人在@你」**。等于告诉模型「这不是跟你说的」，然后问它要不要插嘴——**问错了问题**。日志里是 `主动接话：保持沉默或上下文已更新`，消息被丢掉。

## 做法：不猜，交给模型判断

你说得对，这件事 DeepSeek 自己能判断。关键词规则区分不了「哪个文档啊」和「晚上吃啥」——两句都没有 @、都没有名字、长度语气都差不多，差别只在**语义是否承接**。这需要理解力，不是模式匹配。

所以 `src/followup.ts` 不做任何猜测，只负责**在正确的时机把正确的问题交给模型**：

1. 机器人在群里说话 → 开一个 **90 秒**窗口
2. 窗口内来了没有 @ 的消息 → 带上上下文问模型：

```json
{
  "你最近说过":   ["我觉得应该先看文档"],
  "群里最近的消息": [{"speaker":"成员1","text":"这个怎么搞"}],
  "这条新消息":   "哪个文档啊 我没找到"
}
```

提示词让它先判断「是不是在回应你、追问你、反驳或赞同你」，依据是**话题是否承接、是否在问你提到过的东西**；是就自然回应，不是就 `{"reply":false}` 沉默。

实测：

```
接话是冲着机器人的（哪个文档啊） -> 回复了
接话是聊别的（话说晚上吃啥）    -> 沉默
连续 3 条无关消息            -> 判断 3 次后关闭窗口
```

## 三个防滥用的设计

**连续 3 次判断为「不是」就关窗口。** 否则群里每来一条消息都要调一次 API。判断有回应意图但尚未成功发送时不续窗；机器人成功发言后才重置。

**窗口 90 秒，不是 3 分钟。** 我最初写了 3 分钟，结果测试 `a quiet room ends by itself and then needs a new @` 炸了——它比最小会话超时（2 分钟）还长，会把一个已经正常结束的会话悄悄复活。90 秒短于任何合理的会话超时，回应你刚说的话本来也来得很快。**这是测试发现的真实缺陷，改的是代码。**

**主动插话不开窗口。** 测试 `one-off proactive groups never open a room` 暴露的另一个问题：机器人主动插一句嘴，不应该因此把自己拖进一段对话。用户把群设成「偶尔接话」，那就是他要的行为，一次插话不该越过这个设置。只有**回应别人**（被 @、被引用、被点名、会话模式内）才开窗口。

## 改了一个旧测试

`tests/scheduler.test.cjs` 里 `窗口已结束` 那条断言原本期望「合并批次结束后，同一个人不带 @ 的下一句被丢弃」——正是你要改掉的行为。现在它会被送去判断（不是被并入上一批）。断言改成验证「走的是判断流程、用的是判断提示词、且不是批次延长」，并注明原因。

另外两个失败**没有**改测试，改的是代码——见上。

## 现在的完整判断链

| 情况 | 处理 |
| --- | --- |
| @ 机器人 | 直接回复 |
| 引用机器人的消息 | 直接回复 |
| 喊机器人名字 | 直接回复 |
| **机器人刚发言后的下一条** | **交给模型判断语境** |
| 会话模式窗口内 | 原有逻辑 |
| 其余群聊消息 | 偶尔接话（参与度滑块控制） |
