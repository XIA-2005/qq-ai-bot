# v0.9.0：本地用量后台（总用量、模型、趋势、明细）

日期：2026-09-23

## 用户确认的范围

用户要求一个能看「总共使用量、使用模型等等」的后台，并确认：形态为独立网页后台；新增维度为按模型拆分、时间趋势、逐次调用明细（可导出）；现有 `usage-ledger.json` 历史数据保留并平滑升级。

因此本次是在既有估算体系之上**增加报表维度**，不重做计价：金额仍由 `src/usage-ledger.ts` 按 Token 与捕获单价估算，仍是人民币估算而非实际账单。后台不查询账户余额、不发起任何额外模型请求、不修改自动回复策略。

## 数据结构与迁移

新增 `src/usage-analytics.ts`，作为聚合桶之外的附加统计层，累加的是 ledger 已经算好的同一批整数量，因此不会自造或丢失金额。

维度与上限：

| 维度 | 键 | 上限 | 超限行为 |
| --- | --- | ---: | --- |
| 按模型 | 模型 ID | 64 | 超出并入「未知模型（旧版记录）」 |
| 按天 | 本地时区 `YYYY-MM-DD` | 400 | 丢弃最旧的天，总额不受影响 |
| 按小时 | 本地时区 `YYYY-MM-DDTHH` | 336 | 丢弃最旧的小时，总额不受影响 |
| 逐次明细 | 事件数组 | 2000 | 滚动丢弃最旧条目，并置 `eventsTruncated` |

时间键按本地时区生成，图表与用户看到的时钟一致。趋势与明细的窗口裁剪只影响报表，累计总额始终由原有 bucket 承担。

`usage-ledger.json` 版本由 1 升到 2：

- 读取时同时接受 version 1 与 2。v1 文件的总额、分类、对象归属全部保留，不清零。
- v1 的历史调用没有保存模型名与时间戳，因此不倒填、不猜测；新维度从升级后的第一次请求开始累计，界面明确说明这一点。
- 首次写盘即升级为 version 2，沿用原有临时文件 + rename 的原子替换。
- `analytics` 段损坏时，只冻结明细写入并显示不可用原因，**原始字节保持不变**，聚合总额继续可用；这与既有的整份文件损坏策略一致。
- 明细只保存对象号码、用途、模型名、Token 数、金额与状态，不保存 API Key 与聊天正文。

## 记录口径

- 请求开始即在各维度记一次「用量不完整」，结算后再补齐金额，与聚合桶同步；崩溃遗留的在途请求仍显示为不完整。
- 同一票据只结算一次，observer、返回值与 finally 三条路径不会重复累计。
- 非 `deepseek-flash` 模型没有可用单价，只计次数并保持「不完整」，不套用其他模型的价格。
- 缓存拆分缺失时按全部未命中估算，并单列「缓存拆分缺失」次数，不伪装成真实缓存命中。
- API 未返回可用用量的调用，明细状态为「用量不完整」，金额为 0 且不计入已知金额，不当作免费调用。

## 接口与界面

- `src/control.ts` 新增只读 `usageAnalytics()`；没有开放任何写统计的接口。
- `src/web-server.ts` 新增 `GET /api/v1/usage/analytics`，与其他设备接口一样要求已配对设备令牌，并受同一套限流约束；静态资源新增 `/dashboard`、`/dashboard.css`、`/dashboard.js`，沿用既有的严格 CSP 与安全响应头。
- `mobile/dashboard.html`、`mobile/dashboard.css`、`mobile/dashboard.js`：概览卡片、时间范围切换（今天／7 天／30 天／全部）、按天与按小时趋势图、按模型／用途／对象拆分、逐次明细与 CSV 导出。CSV 在浏览器本地生成，导出当前筛选的全部条目，表格只渲染前 300 条。
- 页面为纯自有静态资源，不引用任何外部 CDN、字体或脚本；图表用内联 SVG 绘制。
- 未配对设备访问接口返回 401，页面显示配对指引而不是空数据。

### 重点测试

1. 按模型拆分的金额与聚合总额逐位一致；不支持的模型只计次不计价。
2. 按天／按小时键使用本地时区，且与总额一致。
3. 明细字段固定且不含密钥或正文；重复结算不双算。
4. v1 文件原地升级：总额与次数保留，新维度为空，写盘后版本变为 2。
5. v2 明细跨重启保留；`analytics` 段损坏时冻结写入并保留原始字节，总额仍可用。
6. 明细窗口达上限后滚动丢弃并置位截断标记，聚合计数继续增长。
7. 探针验证：未配对返回 401、静态资源带严格 CSP、异常 Host 返回 421、URL 查询参数被拒、该接口为只读。

## 说明与限制

金额全部为本软件按 Token 与参考单价的估算，不自动判断高峰／空闲／节假日优惠，也未与真实账单对账，可能高于实际扣款。升级前产生的历史调用无法补出模型名与时间分布。后台仍只监听本机，通过既有隧道与设备配对访问，没有新增公开入口。
