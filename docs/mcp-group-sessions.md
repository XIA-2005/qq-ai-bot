# v0.9.0：群聊「@ 一次后持续参与」

日期：2026-09-21

## 用户确认的范围

用户描述：在群里用 @ 唤醒机器人后，希望它不只是回答唤醒者，而是持续参与这个群的聊天，其他群友不需要 @ 也能接着聊。

两个明确选择：

1. 结束方式：**群内冷场后自动结束**（默认 10 分钟没人发言），之后需要重新 @，或由机器人自己判断加入。
2. 回应方式：**都能参与，但按内容选择回应**——共享带发言者标识的群聊上下文，模型判断哪些消息需要回应，其余保持沉默，避免每句话都抢答。

## 实现

- 新增 `src/group-session.ts`：`GroupSessions` 房间表（内存、按群隔离）与 `sessionMessages()` 提示词构造。
- `src/config.ts`：新增 `RouteMode`（`direct` / `ambient` / `session` / `context`）、`Accepted.session` 与 `Accepted.sessionContext`、配置项 `groupSessionIdleMinutes`（1–120，默认 10）。
- `src/profiles.ts`：群回复方式新增 `session`（@ 一次后持续参与）与 `sessionAuto`（持续参与并允许自行加入），`resolveTarget` 返回 `session` 标志；`newlySession()` 用于新增开启的确认。
- `src/engine.ts`：房间路由（@ 开启、房间内普通发言、@ 别人的消息只作上下文）、房间生命周期、冷场定时器、排队的判断任务让位于明确 @、用量与记忆接线。
- `src/onebot.ts`：房间回复作为纯文本发给整个群，不 @ 任何群友；明确 @ 的那条回复仍然 @ 提问者。
- `src/main.ts`、`src/preload.ts` 之外的 UI 层：状态里新增 `groupSessions`（只含群号、来源、成员数、条数、回复次数、预计结束时间，不含聊天正文）；保存对象配置新增持续参与确认。
- `ui/workspace-ui.js`、`ui/app.js`、`ui/whitelist-rows.js`、`ui/index.html`、`ui/workspace.css`：对象设置新增两种模式与确认弹窗、回复规则新增冷场分钟数与实时房间状态、白名单行摘要显示新模式。

## 行为规则

- 房间只在「@ 一次后持续参与」或「持续参与＋可自行加入」的群开启；其他群仍然只回明确 @，或按原来的单独主动接话判断。
- 房间里任何成员的普通文字都进入房间上下文；@ 机器人直接回答，不 @ 时由模型判断是否回应，安静时保持沉默且不发送任何消息。
- 只以「成员1 / 成员2…」代称群友，机器人自己的发言标记为「机器人」；不保存真实昵称，不读取历史聊天。内存中保留最近 16 条、每条最多 400 字符。
- @ 某个群友的消息只记入上下文，不会单独触发请求；@全体、纯图片、超长文本、忽略名单成员既不进入上下文也不延长房间。
- 群里冷场若干分钟自动结束（机器人自己的发言不算发言），结束后需要重新 @；窗口改动对已开启的群立即生效。
- 明确 @ 会丢弃该群仍在排队的判断任务，但不会打断已经在生成的回复；同一条消息不会重复回答。
- 暂停、清空对话、完全退出、对象停用、移出白名单、改回「仅 @ 回复」都会立刻结束房间。持续参与不写入按发言人区分的记忆，改用房间上下文。

## 费用

- 每次判断与每次回复都是真实的模型请求，按群记入累计估算金额，与私聊、试聊、验证分开。
- 持续参与会把该群最近群聊文字交给模型，费用高于只回 @，界面在开启前明确提示并需要确认。

### 验收覆盖

1. 旧配置升级后获得 10 分钟窗口，且不会自动开启房间或启动 QQ。
2. 对象设置里出现四种群模式与冷场分钟数，超范围数值被真实 IPC 拒绝。
3. 取消确认不会保存房间模式；主进程自身也拒绝未确认的持续参与与自行加入。
4. 未 @ 前的普通消息被忽略；一次 @ 开启房间，状态区显示群号、来源、条数与预计结束时间且不含聊天正文。
5. 其他群友不 @ 也能得到回答，请求携带按时间排列的房间记录与稳定成员编号，费用记到该群。
6. 模型选择沉默时不发送任何消息，房间保持开启。
7. @ 别人的消息只作为上下文，不消耗请求，但下一条回答能看到它。
8. 忽略名单、@全体、图片、超长文本都不会进入上下文或延长房间。
9. 冷场后房间自行结束、写入日志、停止请求，状态区清空。
10. 真实 QQ 传输层给房间回复不加 @，明确 @ 的回复仍 @ 提问者。
11. 暂停后所有房间关闭，之后普通群消息不再得到回答。
