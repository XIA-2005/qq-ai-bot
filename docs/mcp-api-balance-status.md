# v0.8.1：API 余额查询与模型状态修复

日期：2026-09-21

## 用户要求与定位

用户要求在软件内查询 API 余额，并修正模型接口一直显示“未验证”的问题。用户未能进一步区分触发场景，故检查全部调用路径。

原问题：`modelState` 是仅存在于 main.ts 的字符串，只在手动 test-model 时更新；自动回复、试聊等成功不更新。每次保存全局配置都重置“未验证”，重启也丢失记录。这是状态追踪问题，不能据此判断用户的真实 Key、模型或网络一定可用。

## 余额接口与安全

依据 DeepSeek 官方文档：
https://api-docs.deepseek.com/api/get-user-balance/

- 固定 `GET https://api.deepseek.com/user/balance`，Bearer 身份验证，只读账户查询，不请求聊天生成。
- 使用 `is_available` 和 `balance_infos`，展示 CNY/USD 的总余额、赠送余额、充值余额和查询时间。
- 金额保留接口十进制字符串，不使用浮点相加或币种转换，也不推算账单。
- 只使用 Store 内已保存的 Key。Key、接口或模型有未保存修改时，界面阻止查询及手动验证，提醒先保存。
- 主进程请求固定官方域名，禁止重定向，12 秒超时、64 KiB 响应上限，验证响应格式和币种。401/402/403/429 及网络错误有清晰提示，不暴露原始响应体或密钥。
- 一次只允许一个余额请求；不自动轮询，不自动启动付费模型验证，不暂停自动回复。
- 刷新失败保留旧结果及原查询时间并标记过期；无成功结果时不伪造 0。余额只留在内存，重启需重新查询。
- 更换或删除凭据中止余额请求并清空旧结果；使用版本号与 AbortController 防止迟到结果进入新账户界面。

## 模型状态修复

新增 `ApiAccount.track` 统一包裹全部实际模型路径，包括自动回复（直接回复及主动接话判断）、独立试聊、手动验证及原有提炼调用。不恢复已取消的聊天记录获取任务。

- 无 Key：未配置 API Key。
- 有 Key 但没有调用记录：已配置，待验证。
- 请求进行中：调用中；手动验证过程明确显示验证中。
- 成功：调用成功、最近成功时间。
- 失败：调用失败、最近失败时间及脱敏原因。
- 重启：同一 API 配置显示上次调用成功/失败，并明确为历史记录，不声称本次已经验证。
- 普通白名单、人设、Token、冷却等修改不重置模型状态。Key、接口或模型身份变化时才清空旧状态；更换 API 配置也清空试聊，避免混用不同凭据的返回。
- 请求取消不等于模型不可用，不能据此记为调用失败或成功；忽略取消的迟到响应也不能变成成功。
- 凭据代次和请求序号防止旧凭据结果或较早并发请求的失败覆盖较新结果。
- 本地 `api-status.json` 仅保存配置身份 SHA-256 摘要、最后结果、成功/失败时间及脱敏错误。无明文 Key、聊天内容、余额或原始错误体。写盘失败只提示历史状态无法保存，不把已成功模型调用改成失败。
- 余额查询成功不把模型标记为验证通过；也不会掩盖已经发生的模型调用失败。

首次升级没有历史记录时，不从“已保存密钥”伪造“调用成功”。需一次正常回复、试聊或明确确认的手动验证成功后建立记录。手动验证仍提示可能计费。

- `src/main.ts`：统一模型追踪、query-balance IPC、凭据变化和退出清理。
- `src/preload.ts`：新增单一受限 IPC 通道，保留来源检查与渲染器隔离。

### 隔离 EXE 验收覆盖

沿用逐行白名单、独立配置、试聊、托盘、退出和重启回归；新增：

1. 未保存凭据不查询，使用已保存凭据，金额原始精度正确展示。
2. 余额查询成功不伪造模型成功。
3. 429 刷新失败保留旧余额、显示旧结果和限流原因。
4. 换 Key 后旧余额请求迟到结果被拒绝。
5. 试聊成功无需手动验证即可更新模型状态，真实聊天计数和记忆仍为零。
6. 手动验证确认可取消，确认后成功更新界面。
7. 模型 401 显示调用失败与 Key 错误；余额查询成功不能遮盖它；模型重试成功恢复状态。
8. 普通参数保存不重置成功状态；重启显示历史成功且余额重新待查询；删除 Key 后清空状态和余额。

所有测试使用临时 user-data-dir、假 Key、本机进程内的模型和 fetch 桩。账户场景通过真实余额解析器、模型解析器、IPC 和渲染器，而非只塞入 UI 数值。所有桩仅在隔离进程内存在，不写入交付 EXE、生产源码或用户配置。没有查询用户真实余额、没有真实付费模型请求、没有登录或发送 QQ 消息，也没有修改开机启动。

验收脚本早期出现的同名变量、模型桩未恢复原生成函数、删除 Key 后仍断言启动待机状态等脚本问题已修复；最终记录来自完整成功运行。
